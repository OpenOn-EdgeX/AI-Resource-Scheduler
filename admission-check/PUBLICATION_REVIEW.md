# AdmissionCheck 업로드 검토 — 2026-10-22

## 판정과 범위

**개발 브랜치와 Draft PR로 공유 가능. 운영용 `main` 병합은 보류.**

이 변경은 Kueue AdmissionCheck 승인·보류 컨트롤러, LSU 자원 풀 예약·반납 연계, 기관 간 자료 구조와 예제를 추가합니다. 기존에 작업 중이던 `POOL_RELEASE` 로그 문구 변경도 포함합니다. 공개 예제의 운영 식별정보는 익명화하고, 배포 템플릿의 자원 풀 주소는 기본 비활성 값으로 제공합니다. 아래 문제를 해결하지 않은 상태에서 운영 정확성이 검증되었다고 간주하면 안 됩니다.

이번 검토는 로컬 테스트와 코드·계약 검사만 수행했습니다. 운영 클러스터의 큐, 테넌트, 배포, GPU/NPU 워크로드는 변경하지 않았습니다.

## 병합 전 해결할 문제

| 우선순위 | 문제 | 로컬 재현 결과 | 필요한 조치 |
|---|---|---|---|
| P1 | Workload의 Pod 배치 제약이 후보 노드에 반영되지 않음 | 템플릿이 `hostname=n2`를 요구하는 Workload에 `Ready`와 `hostname=n1` 업데이트가 반환됨 | Pod selector·required affinity와 자원별 ResourceFlavor 제약을 함께 만족하는 후보만 선택하고 reconcile 회귀 테스트 추가 |
| P1 | 활성 예약 정리가 최근 500개 결정으로 제한됨 | 예약 레코드 뒤에 새 결정 500개가 있으면 전체 이력에는 반납 대상 1개가 있으나 컨트롤러가 조회한 범위에는 0개 | 화면용 이력 페이지와 활성 예약 집합을 분리해 모든 미반납 예약을 정리 |
| P2 | 물리 사용량 계산이 일반 컨테이너만 합산함 | 일반 컨테이너 CPU 1, init 컨테이너 CPU 8, overhead 1인 Pod를 CPU 1로 계산 | init·restartable init 컨테이너와 Pod overhead를 포함한 effective request 계산 및 회귀 테스트 |
| P2 | 예약 응답 타임아웃의 불확실한 결과가 정리 대상에서 빠짐 | RPM이 예약한 뒤 응답이 유실된 경우 `RESERVED_ERROR` 기록은 Workload 삭제 후에도 `to_release()`에서 제외됨 | 불확실한 예약을 추적하고 멱등적으로 조회·반납하는 경로 및 타임아웃 회귀 테스트 추가 |

위 사례는 실제 클러스터 대신 로컬 가짜 Kube 입력과 저장소 레코드로 재현했습니다. 이 문서가 알려진 문제의 수정 완료를 뜻하지는 않습니다.

## 수행한 검증

- 기존 `test_keti_scheduler` 단위 테스트 **8개 통과**. 위 경계 조건을 충분히 다루지 않으므로 이 결과만으로 운영 준비 완료를 판단하지 않았습니다.
- Python 파일 **31개** 문법 검사, JSON 파일 **12개** 파싱, YAML 파일 **39개** 파싱 통과.
- Protobuf 계약 **4개**를 임시 descriptor set으로 컴파일하는 검사 통과.
- 원래 개발 커밋 8개와 공개 복사본에서 알려진 토큰·개인키·URL 암호·SSH 암호 리터럴 패턴 검사: 후보 없음. 패턴 검사에는 탐지 한계가 있습니다.
- 기존 원격 `main` 위에 익명화한 파일 스냅샷을 새 커밋으로 추가합니다. 내부 식별정보가 남은 중간 개발 이력은 공개 브랜치에 포함하지 않으며 원격 이력 재작성·강제 푸시는 사용하지 않습니다.

기존 JSON 자료 구조는 프로젝트의 필드 정의 형식입니다. JSON 파싱 성공은 JSON Schema 검증이나 기관 간 실제 연동 성공을 의미하지 않습니다. 실제 설치, 컨테이너 빌드, GPU/NPU E2E는 이번 게시 검증 범위에 포함하지 않았습니다.
